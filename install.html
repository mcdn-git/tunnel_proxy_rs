安装与构建

三平台一致：同一份源码、同一套命令、同一份二进制行为。所有路径与命令均与仓库 CI 一致。

1. 环境要求

Rust 工具链

需要 Rust 1.75+（工作区使用现代 async 生态：tokio / axum / rustls / quinn / boringtun）。推荐用 rustup 管理工具链：

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustc --version    # 确认版本 ≥ 1.75
cargo --version

C 编译器

部分依赖需要 C 编译器（ring / boringtun 的 C 部分、Windows Wintun 驱动的 FFI）：

平台要求安装示例
Linuxgcc / clang + libc 头文件apt install build-essential
macOSXcode Command Line Toolsxcode-select --install
WindowsMSVC 生成工具安装 Visual Studio Build Tools，勾选「使用 C++ 的桌面开发」

2. 源码构建

Release 构建

git clone <repo-url>
cd tunnel_proxy_rs
cargo build --release
# 产物：target/release/tunnel_proxy（Windows 为 tunnel_proxy.exe）
建议构建 release 版本：含优化，性能为 debug 的数倍。开发调试用 cargo build 即可。

质量门禁（CI 强制）

提交前仓库在 .github/workflows/ci.yml 对三平台矩阵强制执行以下门禁：

cargo fmt --check           # 0 diff
cargo clippy --all-targets  # 0 warning
cargo test --workspace      # 全量测试全绿（当前 215 个）
cargo build --release       # 产物构建

3. 三平台说明

Linux

功能最全的平台。透明代理（redirect）默认用 iptables REDIRECT（需 root）；无 root 时自动回退 TUN 透明代理（需 TUN 设备）。串口 / ICMP / WireGuard / netns 均可用。

macOS

与 Linux 行为一致。redirect / redu 用 TUN 透明代理实现（需管理员权限 + 系统扩展授权）。ICMP 用 raw socket（需 root 或设置 sysctl net.inet.icmp.icmplim）。

Windows

全功能可用：Unix socket 与 named pipe 统一（Runix）、串口、WireGuard、TUN/TAP（需 Wintun 驱动 + 管理员）、ICMP（用 Win32 Winsock API）。全平台对齐是最高准则——无「仅某平台可用」的对外功能。

已知平台差异（2026-08-29 实测）：① sshd（russh server）在 Windows 绑定监听报 os error 10013（russh 库 Windows socket 兼容限制），请部署到 Linux/macOS，或 Windows 用 sshtunnel 客户端连远程 Linux sshd；② runix（named pipe）数据往返正常，但 Windows named pipe 无 POSIX half-close 语义，stdio 客户端在数据完成后可能不自动退出。详见 docs/platform-support.md。

4. Docker

# 构建镜像（多阶段：builder 编译 + 运行镜像）
docker build -t tunnel_proxy_rs .

# 运行 SOCKS5 代理
docker run -d -p 1080:1080 tunnel_proxy_rs socks5 -l 0.0.0.0:1080

# 运行反向穿透 server（需暴露隧道端口与公网端口池）
docker run -d -p 7000:7000 -p 7001-7010:7001-7010 tunnel_proxy_rs \
  pfserver --listen 0.0.0.0:7000 --password mykey --pool 7001-7010
容器内 TUN / 串口 / netns 等设备功能需要 --cap-add NET_ADMIN --device /dev/net/tun 等特权；纯 TCP/UDP 代理无需。

5. 系统服务

systemd（Linux）

# /etc/systemd/system/tunnel-proxy.service
[Unit]
Description=tunnel_proxy_rs
After=network.target

[Service]
ExecStart=/usr/local/bin/tunnel_proxy run -C /etc/tunnel-proxy/router.yaml
Restart=always
User=nobody

[Install]
WantedBy=multi-user.target

systemctl enable --now tunnel-proxy

Windows 服务

用 NSSM 或 WinSW 包装：

nssm install tunnel_proxy "C:\tools\tunnel_proxy.exe" run -C C:\tools\router.yaml
nssm set tunnel_proxy AppDirectory C:\tools
nssm set tunnel_proxy AppStdout C:\tools\out.log
nssm set tunnel_proxy AppStderr C:\tools\err.log
nssm start tunnel_proxy

6. 验证安装

# 版本与子命令
tunnel_proxy --help

# 本地起一个 SOCKS5 代理，验证可用
tunnel_proxy socks5 -l 127.0.0.1:1080 &
curl -x socks5h://127.0.0.1:1080 https://example.com

# 端到端验证（无需外部服务）
tunnel_proxy bench echo -l 127.0.0.1:9000   # 终端 1：echo 目标
tunnel_proxy bench ping -s 127.0.0.1:1080 -e 127.0.0.1:9000   # 终端 2：经代理测延迟

7. 卸载

源码构建无全局写入，删除源码目录与 target/ 即完成卸载；若配置了系统服务，先停服务再删配置。
